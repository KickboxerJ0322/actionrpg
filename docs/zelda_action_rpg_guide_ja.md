# ゼルダの伝説風アクションRPGをこのリポジトリで作る方法（スマホ前提）

> 対象: 個人開発〜少人数開発 / 2Dトップダウン / **iOS・Android向け**

## 0. まず決めること（最初の1日）

- **ゲームの最小仕様（MVP）**を固定する
  - 1つの草原マップ
  - 1つのダンジョン
  - プレイヤー通常攻撃（剣）
  - 敵2種類（近接1, 遠距離1）
  - 鍵→扉→中ボス→ボスの導線
  - 体力ハートUI + ポーション1種
- **技術スタック**（おすすめ）
  - エンジン: **Godot 4.x**
  - 言語: GDScript
  - アセット管理: 仮素材で先に手触りを作ってから差し替え
- **モバイル制約を最初に固定**
  - 目標FPS: 60（最低30を維持）
  - 画面比率: 16:9基準 + セーフエリア対応
  - 片手/両手操作の両対応を想定

## 2. 先に作るべき「核システム」（モバイル向け順）

1. **タッチ移動 + 仮想スティック**（デッドゾーン調整）
2. **タッチ攻撃ボタン + 攻撃方向補正**
3. **被弾・無敵時間・ノックバック**
4. **敵AI（追跡・攻撃）を軽量実装**
5. **部屋遷移・カメラ（画面揺れは控えめ）**
6. **鍵・扉・スイッチギミック**
7. **HUD（親指で押しやすい配置）**
8. **セーブ/ロード（中断復帰対応）**

> コツ: スマホは入力ストレスが最大の離脱要因なので、先に操作感を完成させる。

---

## 3. スマホ向け設計方針

### 入力（最重要）

- 左下: 仮想スティック（移動）
- 右下: 攻撃ボタン / 右中: 魔法ボタン（遠距離） / 必要なら回避・アイテム追加
- ボタンサイズは最低48dp相当、誤タップ防止に間隔を取る
- タップ優先順位を決め、UI上タップで誤移動しないようにする

### パフォーマンス

- 同時敵数を制限（例: 画面内4〜6体）
- エフェクトは短く軽く、半透明の重ねすぎを避ける
- 物理判定を必要最小限にし、毎フレーム処理を削減
- 低スペック端末向けに品質プリセット（Low/Medium）を用意

### セーブ/復帰

- オートセーブ基準: 部屋遷移、宝箱取得、ボス撃破
- アプリ中断（バックグラウンド）時に即保存
- 再開時は「直前部屋の入口」から復帰して破綻を防ぐ

## 4. 4週間プロトタイプ計画（スマホ版）

### Week 1: モバイル操作の手触り
- 仮想スティック + 攻撃ボタン
- 敵1体
- 無敵時間/ノックバック
- 低負荷UI

**完了条件**: 5分遊んで誤操作ストレスが少ない

### Week 2: 探索ループ
- 2〜3部屋接続
- 鍵と扉
- 宝箱
- オートセーブ

**完了条件**: 「探索→戦闘→報酬」の1サイクルがスマホで回る

### Week 3: ダンジョン導線
- 中ボス
- スイッチギミック
- ショートカット導線

**完了条件**: 10分程度のダンジョン体験が成立

### Week 4: ボス + 最適化
- ボス2フェーズ
- 演出（SE、ヒットストップ最小）
- 端末別の負荷調整

**完了条件**: 中〜低価格帯端末で安定プレイ

---

## 5. ゼルダらしさをスマホで出す重要ポイント

- 敵の予備動作（telegraph）を長めにして見やすく
- ノックバック方向を明確にして「避けた/当てた」を実感させる
- 部屋ごとに1つの問い（どう進む？どう開ける？）を置く
- 新能力入手後に戻る価値を作る
- セッションを短めに設計（1プレイ3〜8分）

## 7. 開発時チェックリスト（モバイル）

- 主要UIが親指で届く位置にある
- 60FPS目標 / 最低30FPSを維持
- 被弾時の無敵時間が機能する
- ドア/鍵状態がセーブ後も復元される
- 電話着信や中断後の復帰で進行破綻しない

---

## 8. 次の一手（このリポジトリで今すぐやる）

1. Godotで `game/` 配下に新規プロジェクト作成
2. `design/mobile_controls.md` を作成し、UI座標とボタンサイズを確定
3. `player` と `enemy` の1対1戦闘シーンをタッチ操作で実装
4. 低スペック端末想定で計測し、重い処理を早期に削る

---

必要なら次に、以下も作れます。

- Godot用の**モバイル入力テンプレート**
- `MobileInputController.gd` の雛形
- スマホ向け1ダンジョンの具体配置（部屋・敵・鍵導線）

## 9. GitHub Pagesで公開して遊べるようにする

- Godotで `Web` エクスポートプリセットを作成（名前を `Web` に統一）
- `main` へ push すると、GitHub Actions で自動的にWeb版をビルド & Pagesへデプロイ
- 手順の詳細は `docs/github_pages_deploy_ja.md` を参照
- `game/project.godot` が未作成でも、`web/index.html` + `web/game.js` の最小プロトタイプを先に公開して検証可能
